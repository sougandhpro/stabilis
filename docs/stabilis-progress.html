What this is

Stable32 is the de-facto tool for frequency stability analysis. It is Windows-only, closed, GUI-driven, unscriptable and no longer developed. stabilis is an open-core engine for the same job, intended as the free foundation under a paid workbench that produces signed ISO-17025-style reports for calibration labs and oscillator manufacturers.

Two things distinguish it from a reimplementation. First, the Haar wavelet variance is the Allan variance, so classical AVAR is the K=1 case of one framework; higher-order Daubechies filters then buy drift immunity and convergence for steeper noise. Second, confidence intervals are derived from the estimator's own coefficient autocovariance, so they do not require identifying the noise type first — Stable32 looks it up in a table and has no answer when the noise is not one of its five power laws.

The commercial argument for validation. ISO/IEC 17025:2017 clause 6.4.1 defines software as equipment, and 7.11.2 requires laboratory software to be validated before introduction. Its NOTE 2 exempts commercial software “in general use within its designed application range” — an exemption stabilis fails twice over, being new and being open-core, since a lab that patches it explicitly triggers re-validation. An accredited lab therefore cannot adopt this engine unless it ships validation evidence. That evidence is the product's moat, not its overhead.

Results: accuracy against certified values

Every classical variance is a sum of squares of integer linear combinations of the phase samples, divided by an integer. Both NBS14 reference sets are integer-derived, so on them the variance is an exact rational. It is computed independently in fractions.Fraction, with the deviation certified to 50 digits via decimal.Decimal.sqrt(). That gives certified values computed here, to far more digits than any published table, with no dependence on a transcription being correct.

Accuracy is reported as LRE, the log relative error, after the NIST Statistical Reference Datasets convention: it is the number of correct significant digits. float64 carries about 15.95, so these are at the representation limit.

Results: one missing sample

Gap handling is where a metrology tool fails most expensively, because it fails quietly. Integrating frequency to phase with a cumulative sum cannot step over an unknown increment, so a single NaN made every later phase sample NaN — and the estimator, dropping non-finite terms as designed, silently analysed only the data before the gap.

Measured at generation time over 400 realizations of 200 white-FM points with one sample removed at the midpoint, each compared against its own ungapped answer. Old integrates the gapped record in one cumulative sum, which is what the estimator used to do; new segments at the gap, integrates each run from its own zero and pools the coefficients. Bias is the mean signed error and is the figure that matters — on any single record either path can land closer by luck, but only one of them is centred on the right answer.

One sample in two hundred, and the old path was biased low by percent — with no warning and a plausible-looking term count. The bias is systematic and grows with τ, because the surviving terms were not a random subset of the record: they were the first half of it. Scatter falls by roughly an order of magnitude too, which is the direct consequence of keeping 197 terms instead of 99.

The correct cost of a gap is the 2m terms whose window spans it — 3m for the Hadamard and modified families — and that is now exactly what it costs, asserted term by term in tests/test_gaps.py. Frequency input defaults to the segmenting policy and refuses the masking one; phase input keeps masking, which is correct when the timescale ran continuously across the gap. The choice, the number of runs and the longest run are all recorded in provenance.

The residual few tenths of a percent in the "new bias" column is not a defect and does not go away: E[σ̂] = σ·√(2/η)·Γ((η+1)/2)/Γ(η/2), so a deviation estimated from fewer terms is genuinely low on average. It is the same bias the ungapped estimate carries, slightly amplified. Correcting it, and reporting the error bar that goes with it, is M2's job — and the reason this defect had to be fixed first, since it feeds the term count that sets η.

Design decisions worth recording

Scale factors live outside the coefficients

Every estimator returns the coefficient array it averaged, so one confidence-interval implementation can serve all of them. The obvious form is variance = mean(c²), which requires dividing by √2 or √6. That was implemented and then reverted: it makes every coefficient irrational and destroys exactness where the mathematics is exact — the drift identity above failed by one bit. The contract is now variance = scale · mean(c²). EDOF depends only on the scale-free correlation structure, so nothing is lost.

float64 phase is a genuine hazard at this precision

At an accumulated phase of 10³–10⁶ s the float64 spacing is 10⁻¹³–10⁻¹⁰ s, which silently quantizes away exactly the picoseconds sub-nanosecond work cares about. Phase is therefore stored as offsets from an explicit epoch, and construction warns when the spacing approaches the smallest resolved step. The warning is recorded in provenance, not merely printed, so it survives into a report.

The classical estimators are not routed through the wavelet filter bank

The Haar-equals-Allan identity is the intellectual core of the library, but making it the implementation would put boundary handling and shift-equivariance on the critical path for no user-visible gain. Written directly, the identity becomes an independent check of two separate code paths instead of a tautology.

No pickle support, by design

pickle.load on a file arriving from a customer's test rig is arbitrary code execution. .npy covers the same need safely.

Three structural properties are enforced by tests rather than convention: the core computes with scipy and matplotlib absent; every theory page must declare its validation status and name a covering test; and built-in readers and estimators register through the same decorator a third-party plugin would use.

Built

  • M0 — immutable phase/frequency containers with the precision guard, provenance with a step log, the plugin registry, tau selection, Kasdin–Walter synthesis, delimited-text reading, theory pages, and a CLI.
  • M1 — adev, oadev, mdev, tdev, ohdev computed directly from phase, gap-aware, plus the exact-rational oracle and the Tier 0 identity suite.

Next

  • M2 — tapered η₁ and η₃ degrees of freedom, the pure-numpy inverse χ², confidence intervals, noise identification, and stabilis validate emitting a versioned evidence report. This is the v0.1 release point and the first genuinely saleable cut.
  • M3 — Greenhall EDOF for error-bar parity with Stable32, the MODWT wavelet layer, TOTVAR with its bias correction, power-law decomposition.
  • M4–M7 — model fitting against the χ² likelihood, instrument readers, realtime ingest and dynamic Allan variance, then the remaining parity tail and the report layer.
Known limitations. No confidence intervals yet, so no uncertainty may be quoted from this version. Expected-value tables relayed from secondary sources are marked UNVERIFIED in the source pending transcription from the SP 1065 PDF; the certified oracle does not depend on them. Instrument readers are not yet validated against real hardware exports. TOTVAR, Theo1, MTIE and the wavelet layer are not implemented.
