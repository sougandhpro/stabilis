# Validation debt

Things this library computes that are **not yet validated to the standard
the rest of it holds to**, each with what is missing and how it gets
discharged. This file exists because ISO/IEC 17025:2017 clause 7.11.2
NOTE 2 exempts commercial software "in general use" — which this is not —
so an accredited lab cannot adopt it without evidence, and the honest
version of that evidence includes what is still owed.

The rule everywhere here is `CLAUDE.md`'s: **a missing expected value
stays missing.** Nothing on this list is closed by inventing a number,
interpolating a neighbour, or writing this library's own output into a
reference table.

Discharged items move out of this file and into
`docs/validation-report.html`, which is generated by `stabilis validate`
and is the artifact that carries measured evidence.

## 1. Stable32 output parity — Greenhall EDOF and the estimators

**Status: in progress, and the first results are in.** Real Stable32 1.62
exports now live in `tests/data/stable32/outputs/` and are scored by the
`interop` tier of the validation report and by `tests/test_stable32.py`.

Measured so far, on synthetic records:

- the `#` term-count column agrees **exactly**, as integers;
- the sigma columns of all five estimators agree to **4.9e-5** worst over
  3229 points — the last digit Stable32 prints;
- `Min Sigma` / `Max Sigma` agree to **5.5e-4**;
- but the **EDOF implied by Stable32's own columns runs ~1.2 % above ours
  for m ≲ 32**, falling to ~0.1 % above m ≈ 40. `allantools` returns our
  value to every printed digit on the same inputs, so two independent
  implementations of the paper agree with each other and disagree with the
  program. Cause unknown, recorded in `theory/greenhall.md`, worth under
  0.06 % on a 68.27 % bound.

**What remains:** the session so far covers this project's own synthetic
records. Still owed are `PHASE.DAT`, the NBS suites, and real WR/OCXO
data — the last of which matters most, being the only case where the data
was not generated by the tool under test. Run sheet at
`tests/data/stable32/README.md`.

`stats/greenhall.py` reproduces the algorithm behind Stable32's `Alpha`,
`Min Sigma` and `Max Sigma` columns, and `stats/classical.py` reproduces
its sigma columns. What is validated today is the *published algorithm*:

- 18 627 parameter combinations agree with an independent implementation
  of the same paper to 1 part in 10⁹;
- eq. (11)'s term count reproduces every coefficient-array length this
  library builds, across five estimators and 250 averaging factors;
- the kernels match sequences worked out by hand from the paper's own
  generalized-autocovariance table, at exact integer equality;
- Monte-Carlo agreement with `2σ⁴/Var(σ̂²)` within 30 % for m ≥ 2.

On the records exported so far, agreement with Stable32's actual output is
now measured too — see the summary above. The claim this library may make
is therefore *"matches Stable32 to the precision it prints, on synthetic
records, with a documented and bounded difference in the degrees of
freedom behind its error bars"*. It is not yet *"matches Stable32"*
unqualified, because no real oscillator record has been through both.

**How the rest gets discharged.** More of the same session. Stable32 1.62
runs natively through WSL interop (`/mnt/c` is reachable; `wine` is not
needed). Run it over `PHASE.DAT`, the NBS suites and real WR/OCXO phase
records, export each statistic at all/octave/decade τ, drop the files in
`outputs/` and fill in `PROVENANCE.md`. **The scoring is already built**:
the reader, the `interop` tier and `tests/test_stable32.py` pick up
whatever is present, so each new export tightens the claim with no code
change. `PROVENANCE.md` is still blank and must be filled — the numbers
above are not yet attributable to a recorded version and settings.

**Do not** vendor `allantools` fixtures to shortcut this: LGPL-3.0 against
this repo's MPL-2.0. It is a test-only differential-testing dependency and
nothing is copied from it.

## 2. The unmodified flicker-PM coefficient, end to end

**Status: partial, and it is the one row that cannot be closed the usual
way. Does not block anything.**

The ten power-law conversion coefficients shipped in `powerlaw_coeffs.py`
are validated against the integrals they descend from and against the
shipped estimators — see `theory/powerlaw.md`. **Nine of the ten are
checked end to end** against synthetic noise of known `h_alpha`.

The tenth, unmodified flicker PM, is not, and the reason is structural
rather than a missing piece of work: its coefficient assumes a brick-wall
`f_h`, and the Kasdin–Walter flicker-PM process is not brick-wall limited —
its spectrum rises to Nyquist and stops. Measured, its constant is **1.764**
where the brick-wall model gives 1.038, an effective `f_h` about 27 % above
Nyquist. Nothing is wrong; the generator and the formula describe different
processes.

**Why this is bounded rather than alarming.** The white-PM row *is* checked
end to end, to 1e-14, because that process is brick-wall at exactly
`f_h = 1/(2τ₀)`. The *modified* flicker-PM row is also checked, because it
carries no `f_h` at all. So the gap sits exactly where theory says it must
and nowhere else, which is itself evidence that the rest is right.

**How it gets discharged.** Either a synthesizer with a genuine brick-wall
filter at a chosen `f_h` — a band-limited generator, which is a real piece
of work and belongs with M8's PSD module — or a real instrument export
whose bandwidth is documented. Until then the flicker-PM `h₁` returned by
the decomposition carries a wider uncertainty than the other four, and the
report says so.

## 3. Instrument readers against real hardware exports

**Status: open, and not yet on the critical path.**

The 53100A / 53230A / 3120A readers (M4) will be written from format
documentation. A reader validated only against its own writer is validated
against nothing. Each binary reader needs a **paired export** — the same
measurement saved by the instrument in both its native format and ASCII —
before it may be trusted, and that pairing is the acceptance test.

## 4. The conformity verdict inherits its interval's accuracy

**Status: open by construction, and bounded rather than unknown.**

`stabilis report` decides conformity on the confidence interval, so the
verdict is exactly as good as the degrees of freedom behind it. The
decision rule itself is fully tested at both boundaries
(`tests/test_report.py`), and the intervals have measured Monte-Carlo
containment — but the two facts do not compose into a stated false-accept
risk, because containment is measured *over an ensemble* while a verdict
is issued on *one record*.

What is missing is a measured operating-characteristic curve: over many
realizations of a unit at a known distance from a limit, the observed rate
of `pass`, `fail` and `indeterminate`. That is the number a laboratory
needs to set a decision rule under ISO/IEC 17025 clause 7.8.6, and it is
cheap to measure with the machinery already here — a Monte-Carlo row in
the validation report, not new theory.

Until then the report states the rule it used and the interval it used it
on, which lets a reader derive the risk themselves. It does not state a
risk figure, and must not be read as having done so.

## 5. The cross-variance has no interop check and no hardware check

**Status: open, and one half of it can never close.**

`multi/cross.py` is validated functionally — the self-cross identity is
exact against a path already certified to 14 digits, the rejection is
measured against the synthetic clock that generated the common part, and
the error bar is measured against Monte-Carlo scatter (`theory/cross.md`
tabulates all three). What it has no equivalent of is item 1's parity
tier, and for a structural reason: **neither Stable32 nor `allantools`
computes a cross-variance**, so there is no published table and no second
implementation to differ from. Manufacturing one from this library's own
output would make the assertion a statement about itself.

That half stays open permanently and is not a defect; it is the price of
being first, and it is why the functional evidence is heavier here than
elsewhere.

The half that *can* close is hardware. Every measurement so far uses
independent synthetic noise, which is precisely the assumption the method
rests on — so the tests confirm the arithmetic and say nothing about
whether two real channels are independent. **A two-channel capture from
the 3120A, ideally with the two channels deliberately sharing a reference
in one run and not in another, is the acceptance test**: the shared-
reference run must show the rejection failing, and if it does not, the
warning this library prints is not detecting the thing it warns about.
That pairing is the same shape as item 3's, and would arrive with the same
data.

## 6. The cross-τ correlation is unmeasured for TOTVAR

**Status: open, narrow, and cheap to close if it ever matters.**

`stats/taucov.py` measures the covariance *between* the τ of one stability
curve, so that a fit to that curve reports an honest parameter uncertainty
instead of one that is too narrow. Its derivation assumes the coefficient
arrays are jointly Gaussian and stationary in the start-sample index, which
is true of the Allan family and is checked against Monte-Carlo scatter for
white FM and random-walk FM in `tests/test_taucov.py`.

**TOTVAR is the exception.** Its coefficients come from a record extended
by reflection, so they are neither independent of each other in the way the
derivation assumes nor stationary across the join. The index alignment
holds — every τ has `N−2` terms starting at the same sample — so the
correlation *is* computed rather than refused, and refusing would be the
arbitrary choice. But it has not been measured against the scatter of
repeated TOTVAR estimates the way the Allan family has.

Discharged by one Monte-Carlo run of the same shape as the existing one:
many realizations, `totdev` on each, sample correlation of `var` between
adjacent τ against what a single record predicts. If it disagrees, the
honest outcome is to decline TOTVAR to the independent diagonal, which the
module already knows how to do.

Everything else with no coefficient alignment — `adev`, the wavelet family,
the Thêo family, any gapped record — already declines with a stated reason
rather than guessing, so none of those is debt.

## 7. The fitted uncertainties have no second implementation to differ from

**Status: open, and one half of it can never close — the same shape as
item 5.**

`fitting/` is validated functionally and the evidence is heavier than usual
because of it. Two rows in `docs/validation-report.html` measure the thing
that matters: over 800 realizations of white FM at a known `h_alpha`, the
stated one-sigma interval contains the true amplitude 0.694 of the time and
the true slope 0.669, against a nominal 0.6827 with a Monte-Carlo standard
error of 0.016. The same fits scored against the interval that ignores the
correlation between τ contain the true slope only 0.525 of the time. The
deviance is calibrated to its own predicted mean, and the optimizer
recovers a model-generated curve to 1e-8.

What none of that is: **a comparison against another implementation.**
Neither Stable32 nor `allantools` fits an arbitrary model to a σ(τ) curve
at all, and no tool in this field computes the cross-τ covariance, so
there is no published table and no second implementation to differ from.
The scipy differential test in `tests/test_fit_models.py` checks that the
optimizer finds the same *minimum*, which is a check on the search and not
on the statistics.

That half stays open permanently and is not a defect. The half that could
close is a **hardware record**: every measurement above uses synthesized
noise whose truth is known because this library generated it. A fitted
Gauss–Markov correlation time on a real disciplined oscillator, checked
against the servo's known time constant, would be the first test where the
answer was not put in by hand. It arrives with the same data item 5 wants.

Also unmeasured, narrowly: the bootstrap. It agrees with the sandwich to
within a third of an interval width on a well-specified fit, which is
tested, but its own coverage has not been scored separately -- the two
routes are validated as one.

## 8. Nothing outside this repository has opened a file we wrote

**Status: open, cheap to close, and it rides along with item 1.**

`io/write.py` writes three formats, one of which exists solely so that
Stable32 and TimeLab can read it. Every test covering it is a round trip
through *our own* reader — `tests/test_io_write.py` says so at the top of
the file, and `theory/export.md` carries the table distinguishing what each
assertion establishes.

This is the mirror image of item 3's rule. A reader validated only against
its own writer is validated against nothing; a writer validated only against
its own reader is in exactly the same position. The two formats agreeing
proves the pair is self-consistent, which is enough to use an export as an
intermediate between two runs of this library and not enough to claim
interoperability with anything.

**How it gets discharged**, and it is one line on an existing run sheet
rather than a new session: while doing item 1, export `alphap0.dat` back out
through `stabilis export data --format stable32`, open *that* file in
Stable32 1.62, and run the same statistics. If the result matches the export
already committed for the original input, the writer is interoperable and
this item closes. If it does not, the difference is the evidence. Add the
step to `tests/data/stable32/README.md`.

The σ(τ) table writer, when it lands, inherits the same debt and the same
remedy — with the additional check that TimeLab can plot the file.

## Not debt

For the avoidance of doubt, these are *already* validated and are not
waiting on anything:

- the classical estimators, against analytic identities at machine
  precision (linear frequency drift gives `avar = D²τ²/2` and `hvar = 0`
  exactly) and against an exact-rational oracle that `stats/` is forbidden
  to import;
- the χ² confidence-interval path, by measured Monte-Carlo containment,
  published in the validation report;
- η₁ and η₃, against `2σ⁴/Var(σ̂²)` measured directly;
- the incomplete gamma and inverse χ², against an exact `Decimal` oracle;
- **the power-law conversion coefficients**, all ten of them, against the
  SP 1065 integrals they descend from and against the shipped `oadev` and
  `mdev` over 300 realizations. The one row with a residual gap is item 2
  above, and it is bounded and explained rather than open;
- **the synthesizer's amplitude** — `h_alpha` is a calibrated, settable
  parameter as of 2026-08-08. Its exact discrete `E[avar]` reproduces the
  closed forms for white FM, white PM and random-walk FM to 1e-16, and the
  requested amplitude is recovered end to end through the real estimator to
  2.3% at 400 realizations. Both are rows in the validation report.
